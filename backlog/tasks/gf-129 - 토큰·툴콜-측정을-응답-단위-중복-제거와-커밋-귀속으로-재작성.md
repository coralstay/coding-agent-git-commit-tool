## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
현재 Tokens-Used 값은 두 가지 이유로 틀렸다.

첫째, 과대계상이다. 트랜스크립트는 한 번의 API 응답을 content 블록 개수만큼 여러 줄로 쪼개 기록하고 각 줄이 동일한 usage를 반복해서 들고 있다. 현재 구현은 줄마다 더하므로 응답 하나를 블록 수만큼 곱한다. 실측: 한 응답이 4줄로 쪼개져 네 줄 모두 usage 합이 87,932였고, 세션 전체로는 줄 단위 26,102,818 대 응답 단위 9,964,308으로 2.62배 차이가 난다.

둘째, 값의 의미가 '직전 커밋 이후 세션에서 소비된 전부'라 그 구간의 무관한 대화가 섞인다. 원하는 값은 '이 커밋에 쓴 양'이다.

조사 결과 귀속에 쓸 수 있는 재료는 tool_use 블록의 input뿐이다 — file-history-snapshot의 trackedFileBackups는 실측으로 전부 비어 있어 쓸 수 없다.
<!-- SECTION:DESCRIPTION:END -->

- 후보: 세션 트랜스크립트 + <세션 디렉터리>/<세션 ID>/subagents/*.jsonl(이름순, 없으면 무시). (requestId, message.id)로 응답 묶기 — usage는 첫 줄 한 번, tool_use는 모든 줄. id 없는 줄은 각자 응답, 키 '<트랜스크립트 디렉터리 기준 파일 경로>:<줄 번호>'. 공백 든 id도 id 없음으로 취급(기록 파일 줄 경계 보호).
- 대상: git diff-tree --root --no-commit-id --name-only -r -z HEAD.
- file_path/notebook_path: 최상위 기준 상대경로, 디렉터리 부분만 realpath(파일 자체 심볼릭 링크는 링크 이름 유지), 저장소 밖은 탈락, 완전 일치. Read도 포함.
- Bash: 경계로 구분된 저장소 상대경로. 왼쪽 경계 = 시작/공백/따옴표/백틱/셸 구두점(= ( < > | ; & , :), 하위 경로 대상은 '/'도 허용(절대경로·../ 표기). 오른쪽 = 끝 또는 [A-Za-z0-9_.-/]가 아닌 글자. 최상위 대상은 '/' 왼쪽 경계 불허(sub/a.txt 오매칭 방지), 대신 ./a.txt와 최상위 절대경로(논리·물리) 허용. 그 밖의 도구는 귀속 안 함.
- 기록: .git/.gitformat-token-attributed(첫 줄 세션 ID, 이후 응답 키). 세션 불일치/없음/손상 → 새로 시작. 성공 시에만 기록(귀속 0개여도). 예전 .gitformat-token-cursor는 읽지 않고 측정 성공 시 삭제.
- 형식: Tokens-Used: in=<I> out=<O>, Tool-Calls: <대상 경로를 건드린 블록 수>. 귀속 없음 → in=0 out=0 (no-attributed-turn) / 0 (no-attributed-turn).

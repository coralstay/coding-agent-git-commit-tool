## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
현재 Tokens-Used 값은 두 가지 이유로 틀렸다.

첫째, 과대계상이다. 트랜스크립트는 한 번의 API 응답을 content 블록 개수만큼 여러 줄로 쪼개 기록하고 각 줄이 동일한 usage를 반복해서 들고 있다. 현재 구현은 줄마다 더하므로 응답 하나를 블록 수만큼 곱한다. 실측: 한 응답이 4줄로 쪼개져 네 줄 모두 usage 합이 87,932였고, 세션 전체로는 줄 단위 26,102,818 대 응답 단위 9,964,308으로 2.62배 차이가 난다.

둘째, 값의 의미가 '직전 커밋 이후 세션에서 소비된 전부'라 그 구간의 무관한 대화가 섞인다. 원하는 값은 '이 커밋에 쓴 양'이다.

조사 결과 귀속에 쓸 수 있는 재료는 tool_use 블록의 input뿐이다 — file-history-snapshot의 trackedFileBackups는 실측으로 전부 비어 있어 쓸 수 없다.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 assistant 줄을 (requestId, message.id)로 그룹핑해 usage를 응답당 한 번만 계상한다
- [ ] #2 한 응답의 tool_use 블록은 여러 줄에 흩어져 있으므로 모든 줄에서 모아 귀속 판정에 쓴다
- [ ] #3 귀속 대상 경로는 git diff --cached --name-only로 얻는다
- [ ] #4 file_path/notebook_path 필드를 가진 도구는 저장소 상대경로로 정규화해 완전 일치로 판정한다
- [ ] #5 Bash 명령은 명령 문자열에 저장소 상대경로가 들어 있는지로 판정하며, 파일명이나 파일명 앞토큰으로는 매칭하지 않는다
- [ ] #6 Tokens-Used를 in=<입력> out=<출력> delta=<구간 전체> 한 줄로 기록한다
- [ ] #7 in은 input_tokens와 cache_creation_input_tokens, cache_read_input_tokens의 합이다
- [ ] #8 delta는 귀속 필터를 적용하지 않은 구간 전체 합이다
- [ ] #9 Tool-Calls는 대상 경로를 실제로 건드린 tool_use 블록 개수다
- [ ] #10 구간에 턴이 없으면 in=0 out=0 delta=0이고, 턴은 있으나 귀속된 게 없으면 no-attributed-turn 사유를 남겨 진짜 0과 구별된다
- [ ] #11 트랜스크립트를 읽을 수 없으면 사유 슬러그와 함께 unavailable로 남긴다

GF-108(checks 5종 Python 포팅)에서 `tests/consistency.bats`의 바이트 동일성 검사
3건을 삭제했다. 이 저장소는 "로직은 공유하지 않고 파일마다 독립적으로 중복을
유지하되, drift는 테스트로 잡는다"를 설계 원칙으로 문서화해 왔다(decision-8,
decision-9). 그 원칙의 집행 장치였던 검사를 없앴으므로, 근거를 남기지 않으면
나중에 두 방향 모두로 잘못 복원될 수 있다 — 검사를 되살리거나, 반대로 "중복을
유지할 이유가 없어졌다"며 공유 모듈로 합쳐버리거나.

## 지운 것

셋 다 훅 소스를 `awk`로 떠서 사본끼리 텍스트가 같은지 비교하는 방식이었다.

| 검사 | 대상 | 관련 |
|---|---|---|
| `resolve_self()` 동일성 | commit-msg, pre-commit, post-commit, checks/{cpp,sql,java}.sh 6곳 | GF-62 / GF-72 |
| TASK_PREFIX/BRANCH 계산 블록 동일성 | commit-msg, post-commit 2곳 | GF-70 |
| gitformat.conf 읽기 가드 동일성 | 위 6곳 + install.sh, 7곳 | GF-76 |

## 왜 지웠나

이 검사들은 **행위가 아니라 특정 구현 언어의 소스 모양**을 검증한다. 훅이 sh에서
Python으로 옮겨가면 매번 같이 고쳐야 하고, 고쳐봐야 "글자가 같다"는 것 외에는
아무것도 보장하지 않는다.

GF-108에서 유저가 두 단계로 판단했다.

1. 먼저 "리팩토링할 때는 테스트 코드를 절대 고치지 마라"(마틴 파울러의 규칙)는
   원칙을 제시했다.
2. 이어서 이 건에는 그 원칙을 적용하지 않기로 했다 — **"이 건은 테스트 삭제해도
   돼. 리팩토링이라기보단 언어를 바꾸는 작업이라."** 리팩토링은 외부 동작을 바꾸지
   않으므로 테스트가 안전망으로 그대로 서 있어야 하지만, 파일명과 구현 언어 자체가
   바뀌는 포팅에서는 소스 텍스트에 묶인 검사가 안전망 역할을 할 수 없다.
3. 그리고 방침을 정했다 — **"기능 테스트, 즉 행위 검증만 남기고 언어 종속적인
   테스트는 삭제해라."**

## 무엇이 대신하는가

삭제 전에 셋 다 대응하는 행위 검증이 이미 있는지 확인했다. 이 대응 관계가 이
문서의 핵심이다 — 같은 회귀가 여전히 잡힌다는 근거이기 때문이다.

| 지운 검사 | 대신 잡는 행위 검증 |
|---|---|
| `resolve_self()` 동일성 | `tests/robustness-dispatch.bats`의 `[GF-16 회귀]` 케이스. template/ 심볼릭 링크로 설치된 새 저장소에서 실제로 커밋을 태워, pre-commit이 checks/를 정확히 찾는지 본다 |
| TASK_PREFIX/BRANCH 블록 동일성 | `tests/robustness-injection.bats`. 브랜치별로 실제 커밋을 만들어 `Task-Id: GF-N` 트레일러가 정확히 붙는지 확인한다 — commit-msg의 검증과 post-commit의 재파싱이 어긋나면 여기서 깨진다 |
| conf 읽기 가드 동일성 | `tests/conf-guard.bats` 7건. conf를 실제로 깨뜨린 사본으로 각 파일을 직접 실행해 종료 코드가 0이 아니고 명확한 에러 메시지가 나오는지 본다 |

세 번째가 특히 분명하다. 원래 `consistency.bats`는 가드 블록의 텍스트가 같은지만
봤고, GF-77에서 "텍스트가 같다고 실제로 동작하는 건 아니다"라는 이유로
`conf-guard.bats`가 런타임 검증으로 추가됐다. 즉 더 강한 검사가 이미 옆에 있었고,
약한 쪽을 지운 것이다.

## 중요: 중복 유지 원칙은 폐기되지 않았다

**검사가 사라진 것을 "이제 파일 간 중복을 합쳐도 된다"는 신호로 읽으면 안 된다.**

decision-16이 Python 전환을 결정하면서도 이 점을 명시했다 — "Python에는 `import`가
있지만 공유 모듈을 만들지 않는다. 파일 하나를 읽으면 그 훅의 동작을 독립적으로
전부 파악할 수 있다는 성질은 sh 때문에 생긴 제약이 아니라 이 저장소가 지키려는
감사 가능성의 일부다."

바뀐 것은 **그 원칙을 무엇으로 지키는가**뿐이다. 소스 텍스트 비교에서 행위 검증으로
옮겼다. 원칙 자체는 그대로다.

## 남긴 것

`consistency.bats`에는 2건이 남았다. 둘 다 구현 언어와 무관한 설정/문서 값의
일치만 본다.

- `gitformat.conf`의 커밋 타입 목록과 `.gitmessage`의 타입 목록 일치 (GF-68)
- `gitformat.conf`에 각 훅이 참조하는 키가 전부 존재하고 값이 비어있지 않음 (GF-61)

## 파급

- **GF-112 AC #5**("동일성 검사 대상 경로를 Python 파일로 갱신한다")는 갱신할 검사가
  없어 무효가 됐다. GF-122에서 제거했다.
- **GF-120**("동일성 검사 대상 목록에 python.sh/ts.sh가 빠진 게 의도인지 누락인지
  확인")은 그 목록 자체가 사라져 무효가 됐다. GF-122에서 종료했다.
- **DRAFT-16**(bats 테스트 스위트 재설계)의 착수 순서 5번이 "consistency.bats의
  바이트 동일성 검사를 유지할지 결정한다"였는데, 여기서 답이 났다. 다만 DRAFT-16이
  검토 선택지로 적어둔 "pytest 전환으로 내부 함수 단위 테스트를 늘리는 방향"은 위의
  "행위 검증만 남긴다" 방침과 충돌할 수 있어, 재개 시 먼저 정리해야 한다.

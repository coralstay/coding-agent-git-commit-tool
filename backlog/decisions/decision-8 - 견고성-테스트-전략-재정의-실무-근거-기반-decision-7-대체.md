## Context

decision-7에서 견고성 테스트 전략의 근거로 ISO/IEC 25010, ISO/IEC/IEEE 29119-4,
ISTQB 표준 문서를 인용했다. 이 프로젝트는 해당 표준에 대한 공식 인증이나 표준
문서 자체의 정합성 검증을 목표로 하지 않으며, 표준 번호를 근거로 대는 방식을
더 이상 쓰지 않기로 했다. 다만 GF-15, GF-16, GF-30~39에서 실제로 발견된
버그들 — 설계엔 있었지만 구현이 빠졌거나 특수 환경(심볼릭 링크, 스테일 마커,
공백 파일명 등)에서만 터진 케이스 — 을 체계적으로 잡기 위한 반복 가능한
테스트 전략 자체의 필요성은 여전히 유효하다. 이 decision은 decision-7을
대체하며, 테스트 대상(GF-23~28)과 테스트 하네스(bats-core) 선택은 그대로
유지하고 표준 인용 부분만 걷어낸다.

## Decision

- **근거**: 특정 표준 문서 번호나 인증 마크를 인용하지 않는다. 대신 이
  프로젝트에서 실제로 발생한 버그 이력(GF-15, GF-16, GF-30~39)을 근거로,
  "설계 의도와 실제 동작이 어긋나는 지점"과 "일반적이지 않은 입력/환경에서의
  동작"을 테스트로 커버한다.
- **테스트 기법**: 동등분할, 경계값분석, 결정테이블, 상태전이, 페어와이즈,
  구문테스트, 오류추정, 결함주입 — 이 프로젝트의 실제 결함 패턴에 맞는 기법을
  업계에서 통용되는 이름으로만 사용하고, 특정 표준의 조항 번호로 정당화하지
  않는다.
- **테스트 범위**는 decision-7과 동일하게 GF-23~28을 유지한다: commit-msg
  (GF-23), pre-commit/pre-push 디스패처(GF-24), post-commit 상태전이/동시성
  (GF-25), install.sh/template 이식성(GF-26), 보안/인젝션 내성(GF-27),
  GitHub Actions 워크플로(GF-28).
- **테스트 하네스**: bats-core 채택은 그대로 유지한다. `run sh ./hook.sh`로
  배포용 POSIX sh 스크립트를 그대로 구동·검증할 수 있어, hooks/*는 순수
  POSIX sh로 유지하면서 테스트만 dev 전용으로 bash를 쓸 수 있다는 근거는
  표준과 무관하게 유효하다.
- **정적 분석**: ShellCheck(v0.11.0)을 CI에 편입하는 것도 유지한다 — "표준
  기반 정적 테스트"가 아니라 "실질적으로 버그를 잡아주는 도구"라는 실용적
  근거로 재정의한다.
- **실도구 재검증**: sqlfluff/ruff/clang-format/maven 실제 설치 기반 검증
  (GF-22)도 그대로 유지한다.

## Consequences

- decision-7은 이 decision으로 대체(superseded)된다. decision-7 파일 자체는
  과거 기록으로 남겨두고, 새 작업은 이 decision을 근거로 삼는다.
- GF-23 태스크 설명에서도 "ISO 29119-4 기법으로" 문구를 제거하고 기법
  나열로 교체했다(backlog CLI로 수정).
- 표준 문서 유료/무료 여부는 더 이상 이 프로젝트의 관심사가 아니므로 관련
  한계 서술도 함께 제거된다.

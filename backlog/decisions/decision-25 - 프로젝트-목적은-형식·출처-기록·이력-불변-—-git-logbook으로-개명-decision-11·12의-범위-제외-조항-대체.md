## Context

README와 이름(git-format)은 이 프로젝트를 "커밋 메시지 형식을 정하는 도구"로 소개해왔다.
decision-23의 제목도 "git-format은 커밋 형식만 다룬다"였다. 그런데 실제 설계는 그보다 넓다.

- append-only 이력 정책과 GitHub 원격 강제(decision-24, DRAFT-18/19/20)
- 출처를 측정해 남기는 트레일러: `Tokens-Used`/`Tool-Calls`, `AI-Model`, `Hooks-Commit`
- 커밋을 막는 게이트: `AI-Model` 화이트리스트, `Task-Id` 브랜치명 강제(decision-4), 에디터 경로 거부(decision-18)
- 작업 단위 규칙: 커밋 하나 = 논리적 변경 하나(decision-22)

2026-10-03 범위 점검에서 이것들이 "형식만"이라는 서술과 어긋난다는 게 드러났다. 특히
decision-24와 DRAFT-19는 decision-11(서버측·CI 검증은 범위 밖), decision-12(push 단계는
다루지 않음)와 정면으로 충돌하는데, 그 조항을 대체한다는 기록이 없었다.

유저 판단: **이것들까지 포함하는 것이 이 프로젝트의 목적이다.** 서술을 설계에 맞춘다.

## Decision

**목적: git 이력을 에이전트와 사람의 작업 로그(logbook)로 만든다.** 세 기둥으로 이뤄진다.

| 기둥      | 무엇을 하나                                                    | 해당하는 것                                                                        |
| --------- | -------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 형식      | 사람이 쓰는 부분을 정해진 양식으로                             | 제목·본문 규칙, 에디터 경로 거부, 커밋 단위(decision-22)                           |
| 출처 기록 | 누가·어떤 도구와 모델로·얼마를 들여 만들었는지 자동으로 남긴다 | 트레일러 전체, 토큰 측정, `AI-Model` 게이트, `Task-Id` 브랜치 강제                 |
| 이력 불변 | 한 번 남긴 기록은 다시 쓰지 않는다                             | append-only(decision-24), 로컬 훅 강제(DRAFT-18), 원격 강제(rulesets, DRAFT-19/20) |

세 기둥은 서로를 필요로 한다. 출처 트레일러는 이력이 다시 쓰이면 자기 커밋에 대해 거짓이
되고(decision-24의 실측), 이력 불변은 기록할 내용이 정형화돼 있어야 의미가 있다.

**decision-11·12의 범위 제외 조항을 대체한다.**

- decision-11의 "서버측/CI 기반 검증은 이 프로젝트 범위 밖": 대체한다. 원격 강제는 이력
  불변 기둥의 일부다 — 로컬 훅은 `--no-verify`와 웹 UI 커밋을 막지 못하므로 원격 없이는
  기둥이 완결되지 않는다(decision-24 "강제 계층").
- decision-12의 "push 단계는 다루지 않는다": 대체한다. push된 이력의 보호가 범위에
  들어온다 — 원격 rulesets가 non-fast-forward push를 거부하고(decision-24), 로컬에서는
  `pre-rebase`가 push 여부를 보고 재작성을 막는다(DRAFT-18). 새 push 단계 훅(pre-push)을
  두는 것은 아니다.
- 두 decision의 나머지 판단은 유지한다. pre-push에서 테스트·빌드를 돌리지 않는다.
- **미결**: CI 트레일러 검사(DRAFT-19)를 이 저장소 전용으로 둘지, 컨슈머에게 배포할지는
  정하지 않았다. DRAFT-19에서 정한다.

**decision-19의 `Signed-off-by` 제거 조항을 대체한다 — `Signed-off-by`는 유지한다.**
decision-19(2026-09-25)는 "커미터 정보는 커밋 객체에 이미 있다"며 제거를 정했다. 그 뒤의
decision-24(09-26)는 `Signed-off-by`와 실제 커미터의 불일치를 이력 재작성의 증거로 썼고,
DRAFT-19(09-26)는 그 대조를 CI 검사 항목으로 삼았다. 유저 규칙: 문서끼리 충돌하면 가장
최근 문서를 우선한다. 출처 기록 기둥에서도 이 트레일러는 "기록 당시의 커미터"를 남겨
재작성 여부를 사후에 대조하게 해 준다. decision-19의 나머지 조항(`AI-Agent` 병합,
`Verify-Bypassed` 제거, 키 단위 중복 판정)은 그대로 유효하다.

decision-23의 언어별 lint 제거는 유지한다. 언어 lint는 세 기둥 어디에도 속하지 않는다.
대체되는 것은 그 제목의 "커밋 형식만"이라는 범위 표현뿐이다.

**이름을 git-logbook으로 바꾼다.** git-format은 첫 번째 기둥만 말한다. 항해일지(logbook)는
정해진 양식으로, 순서대로 쓰고, 지난 장은 고치지 않는다 — 세 기둥이 한 단어에 담긴다.
GitHub 저장소는 새로 만들지 않고 rename한다(이력·PR·rulesets 유지, 예전 URL 리다이렉트).

## Consequences

- README의 소개와 "다루는 범위"를 세 기둥으로 다시 쓴다.
- 이번에 바꾸지 않는 이름이 있다.
  - 설정 키·파일명(`gitformat.*`, `gitformat.conf`, `.gitformat-verified`,
    `.gitformat-token-cursor`, `_GITFORMAT_AMEND_GUARD`): 컨슈머의 git config를 깨는 호환성 변경이라 GF-133에서 다룬다.
  - 태스크 접두어 `GF`: 바꾸면 기존 커밋의 `Task-Id`와 어긋난다. 지난 기록을 고치는 것은
    이력 불변과 반대다.
  - 지난 decision·doc·task 본문의 "git-format": 당시의 기록이라 그대로 둔다.
- 범위 판단 기준이 생긴다. 새 기능은 세 기둥 중 어디에 속하는지로 판단한다. 어디에도
  속하지 않으면(decision-23의 언어 lint처럼) 범위 밖이다.
- 원격 강제가 범위에 들어오면서 GitHub 의존이 생긴다. decision-11이 피하려던 벤더 결합이다.
  로컬 훅이 1차 강제이고 원격은 로컬이 닿지 않는 곳만 막는다는 계층 구분(decision-24)으로
  결합을 최소로 둔다.

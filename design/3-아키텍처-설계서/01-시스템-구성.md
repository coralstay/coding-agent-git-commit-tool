# 3.01 시스템 구성

coding-agent-git-commit-tool은 git이 커밋마다 실행하는 Python 훅 셋과, 그 훅들이 값만 공유하는 설정 파일 하나, 훅을 대상 저장소에 연결하는 POSIX sh 설치 스크립트로 이뤄진다 — 별도 프로세스나 서버 없이 대상 저장소의 `git commit` 안에서만 돈다.

## 구성 요소

| 구성 요소 | 종류 | 언제 도는가 · 언제 쓰이는가 | 하는 일 | 구현하는 요구사항 |
| --- | --- | --- | --- | --- |
| `hooks/prepare-commit-msg` | git 훅 (Python 3) | 커밋 객체가 생기기 전, 에디터보다 앞. `--no-verify`로 건너뛸 수 없다 | 재생 · 병합 커밋 면제, 에디터 경로 거부, 검증 마커(`$GIT_DIR/.gitformat-verified`) 기록 | TRL-001 · TRL-008 |
| `hooks/commit-msg` | git 훅 (Python 3) | 메시지 확정 뒤, 커밋 객체가 생기기 전. `--no-verify`로 건너뛴다 | 제목 형식 · 길이, 제목과 본문 사이 빈 줄, 본문 줄 길이, `Fixes` 해시 실재, 브랜치명의 `<prefix>-<번호>`, 비 Claude Code 도구의 `gitformat.aiModel` 존재 · 화이트리스트 검사. 거부할 때 검증 마커를 지운다 | TRL-001 · TRL-002 · TRL-006 |
| `hooks/post-commit` | git 훅 (Python 3) | 커밋 객체가 생긴 뒤. 건너뛸 수 없지만 커밋을 막지도 못한다 | 검증 마커 유무로 우회를 판정하고, 트레일러를 계산해 `git interpret-trailers` → `git commit --amend --no-verify`로 붙인다 | TRL-003 ~ TRL-008 |
| `hooks/gitformat.conf` | 설정 (git config 형식) | 각 훅이 시작할 때 `git config --file`로 읽는다 | 커밋 type 목록, 길이 제한, 트레일러 키 이름, 알려진 모델 ID, 예외 브랜치 기본값, 태스크 접두어 기본값, 마커 파일명. 값만 공유하고 로직은 공유하지 않는다 | TRL-001 · TRL-002 · TRL-006 |
| `install.sh` | 설치 스크립트 (POSIX sh) | 사람이 한 번 실행한다 | `python3` 존재 확인, 대상 저장소의 `core.hooksPath` · `commit.template` 설정. `--global`이면 `template/hooks/` 심볼릭 링크를 만들고 전역 `init.templateDir`를 설정한다 | TRL-009 |
| `template/` | git 템플릿 디렉터리 | `git init` · `git clone` 때 git이 새 저장소의 `.git/`로 복사한다 | `template/hooks/*`가 `hooks/`의 파일을 가리키는 절대경로 심볼릭 링크다. 클론 위치마다 달라 커밋하지 않는다 | TRL-009 |
| `.gitmessage` | 커밋 메시지 템플릿 | `commit.template`으로 연결된다 | 제목 · 본문 · 트레일러 형식 안내 | TRL-001 |
| `tests/test_*.py` | 테스트 (`unittest`) | 개발할 때 `python3 -m unittest discover -s tests` | 임시 저장소(`tests/isolated_repo.py`)에서 실제 `git commit`을 돌려 훅 동작을 검증한다 | 전부 (4.02) |

훅 파일끼리는 서로를 import하지 않는다. 자기 위치 해석, conf 읽기 가드, 태스크 접두어 · 브랜치 계산
같은 겹치는 블록은 파일마다 중복으로 둔다(1.02 P3). conf를 읽지 못하면 각 훅 앞부분의 같은 가드가
즉시 멈춘다 — 빈 값으로 진행하면 원인을 알 수 없는 거부가 된다.

## 커밋 생애주기

커밋 한 번에 훅이 도는 순서다.

![커밋 한 번의 훅 생애주기](../diagrams/01-commit-flow.svg)

| 순서 | 단계 | 커밋 객체 | `--no-verify`로 건너뛰나 | 실패하면 |
| --- | --- | --- | --- | --- |
| 1 | `prepare-commit-msg` | 아직 없음 | 건너뛸 수 없음 | 커밋이 막힌다 |
| 2 | (에디터) | 아직 없음 | — | 에디터 경로는 1번에서 이미 거부된다. 최종 메시지 검증은 `git commit -m` · `-F`로만 한다 |
| 3 | `commit-msg` | 아직 없음 | 건너뜀 | 커밋이 막히고 검증 마커가 지워진다 |
| 4 | 커밋 객체 생성 | **생성됨** | — | — |
| 5 | `post-commit` | 있음 | 건너뛸 수 없음 | 커밋 결과에 영향을 주지 못한다. 트레일러만 빠진다 |
| 6 | `git commit --amend --no-verify` | 다시 만들어짐 | — | 1번 훅이 다시 돌지만 `_GITFORMAT_AMEND_GUARD=1`을 보고 즉시 끝난다. `post-commit`도 같은 가드로 재귀를 끊는다 |

- **재생 · 병합 커밋은 면제한다.** `MERGE_HEAD` · `CHERRY_PICK_HEAD` · `REBASE_HEAD` · `REVERT_HEAD`가 있거나
  source가 `merge` · `squash`면 `prepare-commit-msg`가 아무것도 하지 않는다. 재생 커밋은 이미 검증된 커밋의
  복제이므로 다시 도장을 찍지 않는다(decision-18).
- **`--no-verify` 판정은 마커로 한다.** `prepare-commit-msg`가 마커를 쓰고, 거부한 `commit-msg`는 마커를
  지운다. `post-commit`은 마커를 읽어 지우고, 마커가 없으면 `commit-msg`를 건너뛴 것으로 보고
  `Verify-Bypassed: true`를 붙인다.
- **`post-commit`은 기록만 한다.** 커밋이 이미 만들어진 뒤라 막을 수 없다(1.02 P6). `python3`가 훅 실행
  시점의 PATH에 없으면 1 · 3번은 커밋을 막아 바로 드러나지만, 5번은 트레일러만 조용히 빠진다.
- 검사 · 트레일러 삽입을 `prepare-commit-msg` 하나로 모으는 구조(decision-18 · decision-19)와 이 장의
  구성 사이의 차이는 3.05 설계 결정과 4.03 미결 사항에서 다룬다.

## 트레일러

훅이 붙이는 트레일러다. 키 이름은 `gitformat.conf`의 `[gitformat "trailer"]`에서 읽는다. 메시지에 같은
`키: 값`이 이미 있으면 다시 붙이지 않는다 — 사람이나 에이전트가 직접 쓴 값을 덮어쓰지 않는다.

| 트레일러 | 값 | 값의 출처 | 붙는 조건 | 신뢰 수준 | 요구사항 |
| --- | --- | --- | --- | --- | --- |
| `Task-Id` | `<prefix>-<번호>` | 브랜치명 (`git symbolic-ref --short HEAD`). 접두어는 `gitformat.taskPrefix`, 없으면 conf 기본값 | 브랜치명에 패턴이 있을 때. 예외 브랜치(`main` · `master` · `develop` · `release/*`)가 아니면 패턴이 없을 때 `commit-msg`가 커밋을 거부한다 | 자동 | TRL-002 · TRL-003 |
| `AI-Tool` | 도구 식별자 (예: `claude-code`) | `AI_AGENT` 환경변수의 첫 필드. Claude Code가 하위 프로세스에 주입한다 | `AI_AGENT`가 있을 때 | 프로세스 주입값 — LLM이 만든 값이 아님 | TRL-006 |
| `AI-Tool-Version` | 도구 버전 (예: `2.1.267`) | `AI_AGENT`의 둘째 필드 | `AI_AGENT`에 구분자가 있을 때 | 위와 같음 | TRL-006 |
| `Co-Authored-By` | `Claude <noreply@anthropic.com>` | conf의 `gitformat.coAuthoredBy` | 도구가 `claude-code`일 때만 | 자동 | TRL-006 |
| `AI-Model` | 모델 ID (예: `claude-opus-5`) | Claude Code: 세션 트랜스크립트 (`~/.claude/projects/<slug>/<세션>.jsonl`)의 마지막 assistant `message.model`. 그 외 도구: `gitformat.aiModel` | 모델 값을 얻었을 때. 트랜스크립트 조회 실패는 커밋을 막지 않는다 | Claude Code는 API 응답 그대로 / 그 외는 자가신고(존재 · 화이트리스트만 검증) | TRL-006 |
| `Tokens-Used` | `in=<입력> out=<출력>` | 이 커밋이 바꾼 파일을 건드린 응답(`tool_use`의 경로 대조)의 `message.usage` 합. 입력은 `input_tokens` + 캐시 생성 · 캐시 읽기 입력, 출력은 `output_tokens`. 서브에이전트 트랜스크립트 포함. 응답 하나는 한 커밋에만 귀속된다 | 에이전트 커밋일 때. 실패하면 `unavailable (<사유>)`, 귀속된 응답이 없으면 `in=0 out=0 (no-attributed-turn)` | API 응답 그대로(Claude Code 한정). 귀속은 근사치 | TRL-004 · TRL-005 · TRL-007 |
| `Tool-Calls` | 개수 | 귀속된 응답에서 대상 파일을 건드린 `tool_use` 블록 수 | `Tokens-Used`와 같음 | `Tokens-Used`와 같음 | TRL-004 · TRL-005 |
| `Hooks-Commit` | 짧은 커밋 해시 | 훅이 놓인 클론의 `git rev-parse --short HEAD` | 훅이 클론 안에 있을 때 | 완전 자동 | TRL-008 |
| `Verify-Bypassed` | `true` | 검증 마커의 부재 | `commit-msg`를 건너뛰었을 때 | 자동 | TRL-008 |
| `Signed-off-by` | `<이름> <이메일>` | 커미터 정보 (`git log -1 --format='%cn <%ce>'`) | 모든 커밋 | 완전 자동. 기록 당시의 커미터라 이력 재작성 여부를 사후에 대조하게 한다(decision-28) | — |
| `Fixes` | `<해시> ("<제목>")` | **사람이 쓴다** | 원인 커밋을 알 때만 | `commit-msg`가 해시 실재를 검증한다 | TRL-001 |

`unavailable`의 사유는 `no-session-id` · `transcript-not-found` · `transcript-unreadable` ·
`transcript-parse-failed` · `no-usage-channel`이다. 세션 ID는 트랜스크립트를 찾는 데만 쓰고 커밋에 남기지
않는다(1.02 P10).

## 설정 레이어

값은 두 층에서 온다. 대상 저장소의 git config가 있으면 그쪽이 이긴다.

| 층 | 위치 | 키 |
| --- | --- | --- |
| 내부 기본값 | `hooks/gitformat.conf` | `markerFile` · `taskPrefixDefault` · `branchExempt` · `aiToolClaudeCode` · `coAuthoredBy` · `knownModel` · `type` · `subjectMaxLength` · `bodyLineMaxLength` · `[gitformat "trailer"]` 키 이름 |
| 사용자 오버라이드 | 대상 저장소의 로컬 · 전역 git config | `gitformat.taskPrefix` · `gitformat.branchExempt`(기본값에 더해진다) · `gitformat.aiModel` |

설정 키와 파일명은 기존 설치를 깨지 않도록 옛 이름(`gitformat.*`)을 쓴다.

## 배치

| 설치 방식 | 명령 | git 설정 | 훅이 실행되는 경로 |
| --- | --- | --- | --- |
| 기존 저장소 | `install.sh [대상]` | 대상 저장소의 `core.hooksPath` = 클론의 `hooks/`, `commit.template` = 클론의 `.gitmessage` | 클론의 `hooks/*`를 직접 |
| 새 저장소 | `install.sh --global` | 전역 `init.templateDir` = 클론의 `template/` | `.git/hooks/*` 심볼릭 링크 → 클론의 `hooks/*`. 훅은 `realpath`로 링크를 따라가 conf를 찾는다 |

어느 쪽이든 실행되는 파일은 클론의 `hooks/`에 있는 바로 그 파일이다. `core.hooksPath`를 점유하므로
대상 저장소의 `.git/hooks/*`는 무시된다.

훅이 `$GIT_DIR`에 남기는 상태 파일은 git이 추적하지 않는다.

| 파일 | 쓰는 훅 | 수명 |
| --- | --- | --- |
| `.gitformat-verified` | `prepare-commit-msg`가 쓰고, `commit-msg`(거부 시) · `post-commit`이 지운다 | 커밋 한 번 |
| `.gitformat-token-attributed` | `post-commit` | 세션 동안 자란다. 첫 줄이 세션 ID이고 다르면 새로 시작한다 |

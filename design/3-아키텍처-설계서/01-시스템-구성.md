# 3.01 시스템 구성

coding-agent-git-commit-tool은 git이 커밋마다 실행하는 Python 훅 하나(`prepare-commit-msg`)와, 그 훅이 값을 읽는 설정 파일 하나, 훅을 대상 저장소에 연결하는 POSIX sh 설치 스크립트로 이뤄진다 — 별도 프로세스나 서버 없이 대상 저장소의 `git commit` 안에서만 돈다. 토큰 · 툴콜 계량은 이 컴포넌트에 없다 — 별도 컴포넌트(이름 미정)의 몫이다(decision-31).

## 구성 요소

| 구성 요소 | 종류 | 언제 도는가 · 언제 쓰이는가 | 하는 일 | 구현하는 요구사항 |
| --- | --- | --- | --- | --- |
| `hooks/prepare-commit-msg` | git 훅 (Python 3) | 커밋 객체가 생기기 전, 에디터보다 앞. `--no-verify`로 건너뛸 수 없다 | 재생 · 병합 커밋 면제, 에디터 경로 거부, 메시지 검증(제목 형식 · 길이, 제목과 본문 사이 빈 줄, 본문 줄 길이, `Fixes` 해시 실재, 브랜치명의 `<prefix>-<번호>`, 비 Claude Code 도구의 `gitformat.aiModel` 존재 · 화이트리스트), 트레일러 삽입(`git interpret-trailers --in-place`) | TRL-001 · TRL-002 · TRL-003 · TRL-006 · TRL-008 |
| `hooks/gitformat.conf` | 설정 (git config 형식) | 훅이 시작할 때 `git config --file`로 읽는다 | 커밋 type 목록, 길이 제한, 트레일러 키 이름(본문 72자 예외 목록을 겸한다), 알려진 모델 ID, 예외 브랜치 기본값, 태스크 접두어 기본값. 값만 담고 로직은 없다 | TRL-001 · TRL-002 · TRL-006 |
| `install.sh` | 설치 스크립트 (POSIX sh) | 사람이 한 번 실행한다 | `python3` 존재 확인, 대상 저장소의 `core.hooksPath` · `commit.template` 설정. `--global`이면 `template/hooks/` 심볼릭 링크를 만들고 전역 `init.templateDir`를 설정한다 | TRL-009 |
| `template/` | git 템플릿 디렉터리 | `git init` · `git clone` 때 git이 새 저장소의 `.git/`로 복사한다 | `template/hooks/*`가 `hooks/`의 파일을 가리키는 절대경로 심볼릭 링크다. 클론 위치마다 달라 커밋하지 않는다 | TRL-009 |
| `.gitmessage` | 커밋 메시지 템플릿 | `commit.template`으로 연결된다 | 제목 · 본문 · 트레일러 형식 안내 | TRL-001 |
| `tests/test_*.py` | 테스트 (`unittest`) | 개발할 때 `python3 -m unittest discover -s tests` | 임시 저장소(`tests/isolated_repo.py`)에서 실제 `git commit`을 돌려 훅 동작을 검증한다 | 전부 (4.02) |

훅을 다시 여럿으로 나누더라도 서로를 import하지 않고, 겹치는 블록은 파일마다 중복으로 둔다(1.02 P3).
conf를 읽지 못하면 훅 앞부분의 가드가 즉시 멈춘다 — 빈 값으로 진행하면 원인을 알 수 없는 거부가 된다.

## 커밋 생애주기

커밋 한 번에 훅이 도는 순서다.

![커밋 한 번의 훅 생애주기](../diagrams/01-commit-flow.svg)

| 순서 | 단계 | 커밋 객체 | `--no-verify`로 건너뛰나 | 실패하면 |
| --- | --- | --- | --- | --- |
| 1 | `prepare-commit-msg` — 면제 → 에디터 거부 → 검증 → 트레일러 삽입 | 아직 없음 | 건너뛸 수 없음 | 커밋이 막힌다 |
| 2 | (에디터) | 아직 없음 | — | 메시지 없이 여는 에디터 경로는 1번에서 이미 거부된다. 최종 메시지 검증은 `git commit -m` · `-F`로만 한다 |
| 3 | 커밋 객체 생성 | **생성됨** | — | — |

- **재생 · 병합 커밋은 면제한다.** `MERGE_HEAD` · `CHERRY_PICK_HEAD` · `REBASE_HEAD` · `REVERT_HEAD`가 있거나
  source가 `merge` · `squash`면 `prepare-commit-msg`가 아무것도 하지 않는다. 재생 커밋은 이미 검증된 커밋의
  복제이므로 다시 도장을 찍지 않고, 원래 커밋의 트레일러를 그대로 들고 온다(decision-18).
- **검증이 트레일러 삽입보다 먼저다.** 사람이 쓴 부분만 검증 대상이다 — 훅이 붙인 트레일러 때문에
  커밋이 거부되는 일이 없다.
- **커밋을 다시 만들지 않는다.** 트레일러는 커밋 객체가 생기기 전에 메시지 파일에 직접 쓰므로
  `--amend`도, 재귀 가드도, 우회 탐지용 마커도 없다(decision-18). `--no-verify`로 건너뛸 검사가 없으므로
  `Verify-Bypassed`도 없다.
- `python3`가 훅 실행 시점의 PATH에 없으면 1번이 실패해 커밋이 막히므로 바로 드러난다.

## 트레일러

훅이 붙이는 트레일러다. 키 이름은 `gitformat.conf`의 `[gitformat "trailer"]`에서 읽는다. 메시지에 같은
키의 줄이 이미 있으면(대소문자 무시, 값은 보지 않음) 그 키는 붙이지 않는다 — 사람이나 에이전트가 직접 쓴
값을 덮어쓰지 않는다(decision-19).

| 트레일러 | 값 | 값의 출처 | 붙는 조건 | 신뢰 수준 | 요구사항 |
| --- | --- | --- | --- | --- | --- |
| `Task-Id` | `<prefix>-<번호>` | 브랜치명 (`git symbolic-ref --short HEAD`). 접두어는 `gitformat.taskPrefix`, 없으면 conf 기본값 | 브랜치명에 패턴이 있을 때. 예외 브랜치(`main` · `master` · `develop` · `release/*`)가 아니면 패턴이 없을 때 커밋을 거부한다 | 자동 | TRL-002 · TRL-003 |
| `AI-Agent` | `<도구>/<버전> (<모델>)` (예: `claude-code/2.1.267 (claude-opus-5)`) | 도구 · 버전은 `AI_AGENT` 환경변수(Claude Code가 하위 프로세스에 주입). 모델은 Claude Code면 세션 트랜스크립트(`~/.claude/projects/<slug>/<세션>.jsonl`)의 마지막 assistant `message.model`, 그 외 도구는 `gitformat.aiModel` | AI 도구가 감지되면 항상. 버전 · 모델을 못 구하면 `version-unavailable` · `model-unavailable`로 남긴다. 트랜스크립트 조회 실패는 커밋을 막지 않는다 | 도구 · 버전은 프로세스 주입값. 모델은 Claude Code면 API 응답 그대로 / 그 외는 자가신고(존재 · 화이트리스트만 검증) | TRL-006 |
| `Co-Authored-By` | `Claude <noreply@anthropic.com>` | conf의 `gitformat.coAuthoredBy` | 도구가 `claude-code`일 때만 | 자동 | TRL-006 |
| `Hooks-Commit` | 짧은 커밋 해시 | 훅이 놓인 클론의 `git rev-parse --short HEAD` | 훅이 클론 안에 있을 때 | 완전 자동 | TRL-008 |
| `Signed-off-by` | `<이름> <이메일>` | 커미터 ident (`git var GIT_COMMITTER_IDENT`에서 시각을 뗀 값) | AI 도구가 감지되지 않은 커밋만(decision-30) | 자동. DCO에서 사람의 인증이라 에이전트 커밋에는 붙이지 않는다 | — |
| `Fixes` | `<해시> ("<제목>")` | **사람이 쓴다** | 원인 커밋을 알 때만 | 훅이 해시 실재를 검증한다 | TRL-001 |

세션 ID는 트랜스크립트를 찾는 데만 쓰고 커밋에 남기지 않는다(1.02 P10). 트랜스크립트에서는
`message.model`만 읽는다.

**측정 트레일러는 없다.** `Tokens-Used` · `Tool-Calls`는 붙이지 않는다(decision-31). 메시지에 직접 쓴 그
줄은 지우지도 값을 검증하지도 않는다. 등록 트레일러가 아니므로 평범한 본문 줄이고 72자 제한을 받는다 —
측정 줄만을 위한 예외를 두면 그 자체가 측정과의 결합이다.

## 설정 레이어

값은 두 층에서 온다. 대상 저장소의 git config가 있으면 그쪽이 이긴다.

| 층 | 위치 | 키 |
| --- | --- | --- |
| 내부 기본값 | `hooks/gitformat.conf` | `taskPrefixDefault` · `branchExempt` · `aiToolClaudeCode` · `coAuthoredBy` · `knownModel` · `type` · `subjectMaxLength` · `bodyLineMaxLength` · `[gitformat "trailer"]` 키 이름 |
| 사용자 오버라이드 | 대상 저장소의 로컬 · 전역 git config | `gitformat.taskPrefix` · `gitformat.branchExempt`(기본값에 더해진다) · `gitformat.aiModel` |

설정 키와 파일명은 기존 설치를 깨지 않도록 옛 이름(`gitformat.*`)을 쓴다.

## 배치

| 설치 방식 | 명령 | git 설정 | 훅이 실행되는 경로 |
| --- | --- | --- | --- |
| 기존 저장소 | `install.sh [대상]` | 대상 저장소의 `core.hooksPath` = 클론의 `hooks/`, `commit.template` = 클론의 `.gitmessage` | 클론의 `hooks/*`를 직접 |
| 새 저장소 | `install.sh --global` | 전역 `init.templateDir` = 클론의 `template/` | `.git/hooks/*` 심볼릭 링크 → 클론의 `hooks/*`. 훅은 `realpath`로 링크를 따라가 conf를 찾는다 |

어느 쪽이든 실행되는 파일은 클론의 `hooks/`에 있는 바로 그 파일이다. `core.hooksPath`를 점유하므로
대상 저장소의 `.git/hooks/*`는 무시된다.

훅은 `$GIT_DIR`에 상태 파일을 남기지 않는다. 커밋 사이에 이어지는 상태가 없으므로 커밋 하나의
동작은 그 커밋의 메시지 · 브랜치 · 환경변수 · 설정만으로 정해진다.

# 1.02 원칙

이 컴포넌트의 모든 요구사항이 따라야 하는 불변 규칙이다. 원칙을 바꾸려면 3.05 설계 결정에 결정을 먼저 남긴다.

| ID | 원칙 | 근거 | 최상위 연결 |
| --- | --- | --- | --- |
| P1 | **git 내장 메커니즘만 쓴다.** 배포는 `core.hooksPath`(기존 저장소) · `init.templateDir`(새 저장소)로, 트레일러 조작은 `git interpret-trailers`로, 설정 읽기는 `git config --file`로 한다. ini를 직접 파싱하지 않는다. | 기존 저장소와 새 저장소를 한 메커니즘으로는 덮지 못해 둘을 함께 쓴다(decision-2). 설정을 직접 파싱하면 다중값(`--get-all`) · 따옴표 처리 같은 git 자신의 의미론과 조용히 갈라진다(decision-16) | TRL-009 |
| P2 | **훅은 Python 3 표준 라이브러리만으로, 해석되는 소스 그대로 배포한다.** 설치할 패키지가 없다. 컴파일된 바이너리로 배포하지 않는다. 설치 스크립트(`install.sh`)만 POSIX sh다. | 사용자는 적용 전에 `hooks/` 코드를 직접 읽고 검토할 수 있어야 한다 — "읽는 파일 = 실행되는 파일". 바이너리 배포는 이 약속과 충돌해 기각됐다(decision-16) | TRL-009 |
| P3 | **파일 하나만 읽으면 그 훅의 동작을 전부 알 수 있다.** 훅 사이에 공유 모듈을 두지 않고, 겹치는 블록(자기 위치 해석 · conf 읽기 가드 · 브랜치 계산)은 파일마다 중복을 유지한다. 공유하는 것은 `gitformat.conf`의 값뿐이다. | 감사 가능성의 일부다. 언어 제약에서 온 것이 아니라 이 컴포넌트가 지키려는 성질이다(decision-16) | — |
| P4 | **값은 검증 가능한 출처에서만 얻는다.** 에이전트에게 묻지 않는다. 모델명과 토큰 수는 API 응답을 그대로 기록한 세션 트랜스크립트(`message.model` · `message.usage`)에서, 에이전트 여부는 실재를 확인할 수 있는 신호(`CLAUDE_CODE_SESSION_ID`가 가리키는 파일 · `CLAUDE_PID`가 가리키는 프로세스)로만 판정한다. 존재 여부뿐인 플래그성 환경변수는 판정에 쓰지 않는다. | 자가신고는 진실성을 검증할 수 없다(decision-5). 다른 AI 도구 8종을 조사했지만 세션 상관 채널과 서버가 확정한 모델 값을 동시에 가진 도구가 없어, 그 도구들은 존재 · 화이트리스트 검증까지만 한다(decision-15 · decision-17). 판정 신호는 위조 · 누락이 쉬운 것을 뺐다(decision-20) | TRL-004 · TRL-006 |
| P5 | **측정할 수 없으면 사유와 함께 그렇다고 남긴다.** 틀린 값이나 일부만 집계한 값을 정상값처럼 남기지 않는다. 구성요소를 못 구해도 트레일러 줄은 남긴다(`unavailable (<사유>)`). | 조용한 생략이 곧 잘못된 귀속이다 — 에이전트 커밋이 사람 커밋으로 보이게 된다(decision-20). 과소계상이 알려진 채널의 값도 같은 이유로 받지 않는다(decision-17) | TRL-005 · NFR-005 |
| P6 | **강제할 수 있는 자리에서 강제하고, 강제할 수 없는 자리에서는 기록한다.** 규칙 강제는 `--no-verify`로 건너뛸 수 없고 커밋 객체가 생기기 전에 도는 `prepare-commit-msg`에 모은다. 커밋이 이미 만들어진 뒤에 도는 `post-commit`은 막지 않고 기록만 한다. | git 2.54.0 실측: `prepare-commit-msg`는 `--no-verify`에도 실행되고 `exit 1`로 커밋을 막는다(decision-18, doc-15). 대가로 에디터 경로는 거부한다 — 에디터가 이 훅보다 뒤에 열려 최종 메시지를 볼 수 없다. 건너뛴 검사는 막지 못하는 대신 `Verify-Bypassed`로 남긴다(decision-3) | TRL-001 · TRL-008 |
| P7 | **이력은 append-only다.** 커밋이 만들어진 뒤에는 그 객체를 다시 만들지 않는다. 금지선은 공개(push)된 이력이다 — push 전 로컬 정리는 허용한다. 되돌리기는 revert, 통합은 머지 커밋으로 한다. 로컬 훅이 막지 못하는 것은 원격 저장소 설정이 막는다. | 이력이 다시 쓰이면 트레일러가 자기 커밋에 대해 거짓이 된다(decision-24의 실측). Linux 커널 메인테이너 문서도 공개된 이력을 바꾸지 말라고 한다 | — |
| P8 | **범위는 형식 · 출처 기록 · 이력 불변 세 기둥이다.** 세 기둥 어디에도 속하지 않는 기능(언어별 lint, push 단계 테스트 · 빌드)은 두지 않는다. | 언어 lint는 사용자에게 언어 도구를 전제하게 만들고, 도구 부재 시 조용히 건너뛰다 사고를 냈다(decision-23). 세 기둥이 이 컴포넌트의 목적이다(decision-25). push 단계의 무거운 검사는 범위 밖이다(decision-12) | — |
| P9 | **커밋 하나 = 논리적 변경 하나 = 함수 하나 수준.** 이 규칙은 정책이고 훅이 강제하지 않는다. "커밋 하나 = 파일 하나"는 규칙이 아니라 결과다. | 커밋 사이 구간이 짧을수록 토큰 귀속에 무관한 작업이 덜 섞인다 — 측정 정밀도가 규율에서 나온다(decision-22) | 최상위 P7 |
| P10 | **커밋에 남기면 안 되는 것은 남기지 않는다.** 세션 ID는 트랜스크립트를 찾는 데만 쓰고 커밋에 남기지 않는다. 트랜스크립트에서는 필요한 필드만 읽고 대화 내용을 복제하지 않는다. 인증 정보(`CLAUDE_CODE_MESSAGING_SOCKET` · `_TOKEN`)는 절대 남기지 않는다. | 커밋 이력은 공개 저장소에 영구히 남는다(decision-5 amendment · decision-20) | — |
| P11 | **외부 문서를 저장소에 옮겨 담지 않는다.** 규칙만 뽑아 적용하고, 필요할 때마다 다시 조회한다. | 라이선스가 다른 콘텐츠가 별도 라이선스 레이어를 만든다. 저장소를 단일 라이선스로 두는 것이 vendoring의 편의보다 중요하다(decision-14) | — |
| P12 | **테스트도 표준 라이브러리로 돈다.** 테스트는 `unittest`로 쓰고 `python3 -m unittest discover -s tests`로 실행한다. `pytest` · bats 같은 외부 도구를 요구하지 않는다. | 훅이 "설치할 것 없음"인데 테스트만 외부 도구를 요구하는 비대칭을 없앤다. 트랜스크립트 픽스처를 `json.dumps`로 만들고 트레일러를 개수까지 검증할 수 있다(decision-21) | — |

## 원칙끼리의 관계

- P4 · P5는 한 쌍이다. 검증 가능한 출처에서 값을 못 얻으면(P4) 추측으로 채우지 않고 사유를 남긴다(P5).
- P6 · P7은 "로컬 훅이 어디까지 지킬 수 있는가"의 답이다. 커밋 단계는 `prepare-commit-msg`가 강제하고,
  push된 이력은 로컬 훅으로 지킬 수 없으므로 원격 설정에 맡긴다.
- P2 · P3 · P11은 감사 가능성을 이룬다 — 사용자가 이 컴포넌트를 믿으려면 실행되는 코드를 그대로 읽을
  수 있어야 하고, 그 코드가 다른 라이선스 · 다른 파일에 기대지 않아야 한다.
- P9는 최상위 P7(계층은 코드 단위에 고정된다)의 "커밋 = 함수"를 이 컴포넌트 쪽에서 받은 것이다.
